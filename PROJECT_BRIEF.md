# PROJECT BRIEF: data-sentinel

## Purpose
Portfolio project for Will Irvine, targeting Apple IS&T / AI & Data Platforms software engineering roles (fraud/anomaly detection and reliability engineering). This repo will be reviewed by recruiters and engineers. Code quality, tests, documentation, and commit hygiene matter as much as functionality.

## What we are building
A Python data pipeline that ingests transaction data, engineers features, runs multiple anomaly detection methods, and produces alert reports — with monitoring, tests, and CI treated as first-class.

## Hard rules
1. NO secrets, API keys, tokens, or real personal data anywhere — including commit history.
2. All data is synthetic, generated by code in this repo. No downloaded datasets with license questions.
3. Every phase ends with passing tests (`pytest`) before committing.
4. Commit in small, logical increments with clear conventional messages (e.g., `feat: add z-score detector`, `test: edge cases for feature builder`). Do NOT squash everything into one giant commit.
5. Python 3.11+, standard tooling only: pandas, numpy, scikit-learn, pytest, ruff. No heavy frameworks.
6. Type hints on all public functions. Docstrings that explain WHY, not just what.
7. Keep it honest: this is a learning/demo project. The README should not overclaim (no "production-grade" language).

## Architecture
```
data-sentinel/
├── src/sentinel/
│   ├── __init__.py
│   ├── generate.py      # synthetic transaction data generator (seeded, reproducible)
│   ├── features.py      # feature engineering (rolling stats, velocity, time-of-day, merchant frequency)
│   ├── detectors/
│   │   ├── __init__.py
│   │   ├── zscore.py    # statistical detector (rolling z-score)
│   │   └── isoforest.py # ML detector (scikit-learn IsolationForest)
│   ├── pipeline.py      # orchestrates: generate/load → features → detect → report
│   ├── report.py        # alert report output (console table + JSON artifact)
│   └── monitoring.py    # structured logging, timing metrics, run summary stats
├── tests/               # pytest — aim for meaningful coverage of every module
├── .github/workflows/ci.yml  # lint (ruff) + tests on push/PR, Python 3.11 and 3.12 matrix
├── pyproject.toml
├── README.md
└── PROJECT_BRIEF.md     # this file
```

## Phases — complete ONE phase per working session, commit as you go
### Phase 1 (today)
- Project scaffolding: pyproject.toml, package structure, ruff config
- `generate.py`: seeded synthetic generator producing ~50k transactions (timestamp, amount, merchant_category, user_id, location) with ~1% injected anomalies (amount spikes, velocity bursts, odd-hours activity) and a labels column for evaluation
- Basic tests for the generator (reproducibility with seed, anomaly rate, schema)
- CI workflow running ruff + pytest
- Commit and push. CI must be green.

### Phase 2
- `features.py`: per-user rolling statistics, transaction velocity, time-of-day encoding, merchant frequency
- `zscore.py` detector with configurable threshold
- Tests for both. Green CI.

### Phase 3
- `isoforest.py` detector
- `pipeline.py` orchestration with a CLI entry point (`python -m sentinel run --n 50000 --seed 42`)
- Evaluation: precision/recall of each detector against injected labels, printed in the run summary
- Tests. Green CI.

### Phase 4
- `monitoring.py`: structured logging (JSON logs), per-stage timing, run summary (rows processed, anomalies flagged, detector agreement rate)
- `report.py`: console summary table + JSON report artifact written to `reports/`
- Tests. Green CI.

### Phase 5
- README rewrite: problem statement, architecture diagram (mermaid), quickstart, sample output, evaluation results table, limitations section, "what I'd do next" section
- Badge for CI status
- Final polish pass with ruff
